# JaguarTV 当前工作流程（服务器审核版）

## 第一步：准备采集入口

系统默认开启 YouTube、Bilibili、抖音、小红书、TikTok、Facebook 六个平台入口。

- YouTube、Bilibili、TikTok、Facebook 优先走 `yt-dlp` 能力。
- 抖音优先走 SkillHub 的 `douyin-downloader` / 本地 Douyin API 服务。
- 小红书优先走 URL 导入，批量采集可接 MediaCrawler 产出的 JSONL。
- MediaCrawler 作为外部素材池入口，负责把抖音、Bilibili、小红书、TikTok 等平台采集结果导入候选库。

## 第二步：关键词发现与候选入库

系统按 `config/keywords.demo.yaml` 中的关键词搜索素材，并把结果写入 `workspace/factory.db`。

入库时会做三件事：

- 识别平台、标题、播放量、时长、语言。
- 按热度、互动、相关性、可剪辑性、巴西适配度打分。
- 执行时长门禁：超过 `1800` 秒（约 30 分钟）的源视频直接标记为 `TOO_LONG`，不进入下载制作。

## 第三步：登录态与 Cookie 检查

如果平台要求登录或风控校验，系统会保留失败原因。

当前常见阻断：

- YouTube：提示 `Sign in to confirm you're not a bot` 时，需要 YouTube cookies。
- Bilibili：返回 `HTTP 412` 时，需要 Bilibili cookies。
- 抖音：本机 `8000` 端口采集服务未启动或未配置 Cookie 时无法搜索。
- 小红书：关键词搜索不走内置接口，建议用作品 URL 导入或 MediaCrawler JSONL。
- TikTok：服务器当前 `yt-dlp` 不支持关键词搜索，需要 Cookie、用户/标签入口，或接 Apify。
- Facebook：关键词搜索不稳定，建议直接 URL 或后续接 Apify。

## 第四步：下载源素材

只有状态为 `DISCOVERED` 且未超过 30 分钟的候选会进入下载。

下载完成后，源视频和字幕文件放到：

```text
workspace/jobs/<candidate_id>/
```

如果下载失败，候选状态变为 `DOWNLOAD_FAILED`，页面会显示最近失败原因。

## 第五步：内容类型识别

制作前会自动判断内容类型：

- 足球赛事、体育集锦：走体育高光策略。
- 舞蹈音乐、搞笑生活：保留源音乐优先。
- 解说知识、中文字幕内容：走葡语本地化策略。
- 高风险版权类型：如果没有明确授权状态，直接阻断制作。

## 第六步：合规门禁

当前配置要求素材必须具备已核验权利状态。

制作时必须选择：

- 自有素材
- 已获授权
- 公共领域
- CC BY 许可
- 已由负责人核验

体育赛事、影视剪辑、少儿动画、剧集类内容默认属于高风险素材。系统不会为了绕过版权检测而去水印、去平台标识或规避查重。

## 第七步：按内容类型选择处理策略

系统把素材分为三类执行：

- 第一类：检测到中文字幕。生成巴西葡语男声配音、生成葡语字幕，并对原中文字幕区域做 OCR 识别与模糊。
- 第二类：无中文字幕、无明确中文语音证据。保留源音或源音乐，不额外生成旁白字幕。
- 第三类：无屏幕字幕，但标题/语言判断显示为中文语音内容。生成巴西葡语男声配音，但不强行加屏幕字幕。

这样处理的目的：有字幕就翻译并覆盖难点；没有字幕就不乱加字幕，避免成片看起来像机器硬套。

## 第八步：长视频智能切片

系统先看源视频长度：

- 低于或约等于 1 分钟的源视频：按短视频处理，保留完整内容，不做智能切片。
- 超过约 1 分钟、且低于 30 分钟的源视频：进入智能切片。
- 超过约 30 分钟的源视频：标记 `TOO_LONG`，不下载制作。

足球长视频的切点会综合：

- 观众欢呼、解说突然变大声等音量骤增。
- 进球、射门、扑救、抢断、传球、助攻、过人等关键词。
- 镜头运动、场景变化、慢动作/回放信号。

系统最多产出 3 个高光片段，每段控制在 `12-60` 秒。

## 第九步：葡语配音与音频处理

本地化素材使用巴西葡语男声：

```yaml
edge_tts_voice: pt-BR-AntonioNeural
tts_rate: 1.08
speech_style: excited_sports_male
```

有中文对白或字幕时，系统生成更亢奋的葡语讲解，并叠加 Funk 风格 BGM。没有对白证据时，优先保留源音乐。

## 第十步：品牌包装

当前只做轻量品牌包装：

- 视频尾部固定插入 2 秒全屏宣传图。
- 近似 9:16 的竖屏视频使用绿色背景宣传图。
- 近似 16:9 的横屏视频使用蓝色背景宣传图。
- 图片全屏填充，不额外生成复杂包装动画。

## 第十一步：生成审核包并放到服务器

成片通过 QA 后，系统生成审核包：

```text
video.mp4
cover.jpg
metadata.json
review.json
```

审核包会先写入本地：

```text
workspace/ready_for_review/<package_id>/
```

然后同步到服务器审核目录：

```text
/opt/jaguartv-content-factory-vnext/workspace/server_media/review/<package_id>/
```

内部人员打开 `https://factory.jarg.top/` 即可在内容库存里看到待审核素材，并可以点击预览、通过、返工。

## 第十二步：Reaction 渲染

制作弹窗中可以开启 Reaction：

- 画中画
- 上下分屏
- 左右分屏

Reaction 素材必须使用服务器路径或通过控制台上传。开启后，系统会把原内容和 Reaction 视频合成到最终审核包里。

## 当前已知前置条件

要让六个平台稳定跑通，需要补齐以下登录态或服务：

- YouTube cookies：解决机器人校验。
- Bilibili cookies：解决 412 风控。
- 抖音采集服务与 cookies：启动 `127.0.0.1:8000` 服务。
- 小红书作品 URL 或 MediaCrawler JSONL。
- TikTok cookies / Apify / 可用用户或标签入口。
- Facebook 具体视频 URL / cookies / Apify。
